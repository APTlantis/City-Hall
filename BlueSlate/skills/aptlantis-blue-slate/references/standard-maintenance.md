# Standard maintenance

For an authorized Blue Slate standard update, read the current suite and City Hall/SFDS/WGS records before changing identity, maturity or authority. Inspect all contributed directories and compare their source roles, versions, generated output and actual runtime evidence. Preserve exact physical names and pre-change evidence; check callers before consolidating duplicate or superseded files.

Use the version policy in SFDS. Keep manifest, README, primary/overview specification, token metadata, changelog, adoption/validation guides and generated outputs aligned. Register source contracts, templates, examples, validators, visual provenance and the skill in the suite map/manifest. Preserve frozen consumer interfaces or document a deliberate incompatible migration.

Record the promotion source and canonical destination in a migration note. A working copy outside zoning can be explicitly reviewed and adopted without pretending that a physical move or prior zoning registration occurred. Do not silently create a second authority.

Update `WGS/Documentation-Suite-Roadmap.md` and relevant City Hall navigation. Inspect root/parent registries and responsibility matrices; change them only when their recorded facts change. Preserve dated historical snapshots. State why unchanged extended records need no edit.

Run the compiler freshness/conversion/contrast checks, compiler regressions, suite validator and SFDS suite validation. Keep a report with actual results and limitations. Maturity follows evidence: Candidate allows pilots; Stable and Reference need support for their claimed adoption scope. Do not turn generated boards, package files, source tests or placeholder adoption records into runtime proof. NeonInk and SESM remain separate authorities.

When replacing this skill or its resources, check real use cases: auditing without palette retuning, a fresh layout, a legacy adapter migration, an image extraction and an SVG metadata job. Ensure guidance routes to actual files and executable interfaces without requiring unrelated workflows for a small task.
