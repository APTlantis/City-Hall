# Blue Slate suite map

| Layer | Files | Meaning |
| --- | --- | --- |
| Suite governance | `BlueSlate.manifest.toml`, `README.md`, `AGENTS.md`, `CHANGELOG.md`, `Migration-0.5.md` | Identity, authority, maturity and compatibility. |
| Domain specification | `spec/BlueSlate.DesignSystem.md`, `spec/BlueSlate.Overview.md`, `spec/layout/BlueSlate.LayoutPatterns.md` | Design rules, surface anatomy, states and ten layout patterns. |
| Domain source contract | `spec/tokens/BlueSlate.Tokens.toml`, `spec/tokens/Token-Contract.md`, `tools/compile_blueslate.py` | Token data, documented schema and executable contract. |
| Adopter template/example | `templates/BlueSlate-Adoption.toml`, `examples/BlueSlate-Adoption-Example.md` | Versioned profile and evidence record; separate from the suite manifest. |
| Implementation aids | `generated/`, `starter-packs/`, `spec/frameworks/`, `examples/BlueSlate-Specimen.html` | Current outputs and explicitly bounded pilots. |
| Visual evidence | `spec/mockups/`, `spec/references/`, `reports/` | Reviewed references, provenance, inventory and measured results. |
| Agent guidance | `skills/aptlantis-blue-slate/` | Task-scoped theming, layout, adapters, assets, auditing and standards maintenance. |

Suite checks establish parseability, source references, generated freshness, registered artifacts and the declared opaque contrast pairs. Domain conformance requires checking the adopter's actual rendered surface. The standalone specimen and native XAML samples are examples, not a completed reference implementation.
