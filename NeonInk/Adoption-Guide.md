# NeonInk Adoption Guide

Adopt NeonInk when a UI, desktop app, website, dashboard, generated asset, or design document needs consistent semantic color and visual intent.

## Steps

1. Read `Governance-Index.md`.
2. Choose the relevant contract: core NeonInk, app surface guidance, NIPC, AIC, APGC, TagTheme, or component patterns.
3. Record the adopted contract in the project manifest.
4. Preserve semantic meaning when translating colors or themes.
5. Validate assets against the relevant contract before release.

## Desktop Applications

For app adoption, define:

- semantic roles for active, verified, caution, critical, disabled, and inactive states;
- icon mapping for repeated file, object, operation, or health types;
- glow usage rules for active/focused/high-risk surfaces;
- dense-list behavior that combines icon, text, and accent rather than color alone;
- accessibility checks for neon text and borders on dark backgrounds.

## SFDS Relationship

Use SFDS to maintain NeonInk as a standard suite.
Use NeonInk to govern semantic color, theme behavior, design intent, component patterns, desktop app surfaces, and generated design assets.
