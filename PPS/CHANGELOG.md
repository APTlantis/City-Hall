# PPS Changelog

## Unreleased

- Added project responsibility postures for `personal`, `shared`, and `adoptable` projects.
- Clarified that a release version can be an explicit complete project endpoint when it satisfies the proposal, delivery standard, and responsibility posture.
- Added lightweight version milestone sketches so PPS proposals can define flexible early-version completion shapes.
- Added `PROJECT-READMAP.toml` generation to PPS onboarding so evaluators receive a bounded read-first map instead of searching whole project trees by default.
- Added proposal manifest validator, readiness/persona schema vocabulary, CI usage guidance, JSONL export format, and delivery-standard mapping examples.
- Added `tools/pps_new.py` to generate proposal and entity-manifest skeletons.
- Added PPS to WGS lifecycle mapping guidance.
- Added a worked proposal-to-delivery handoff example.
- Added archival proposal snapshots demonstrating readiness transition evidence.

## 0.2.2 - 2026-06-12

- Added SIS to the delivery-standard guidance for service and infrastructure project proposals.

## 0.2.1 - 2026-06-11

- Added filled proposal examples for desktop applications, websites, datasets, and new standard suites.
- Expanded PPS reference examples so different project classes have practical starting points.

## 0.2.0 - 2026-06-11

- Promoted PPS to candidate maturity as the project-intent standard.
- Expanded the primary specification with WGS lifecycle alignment, operational personas, technical direction, constraints, risk controls, roadmap phases, proposal blockers, and agent-use rules.
- Clarified that PPS is the north star for project intent while WGS owns placement and delivery standards own execution.

## 0.1.3 - 2026-06-10

- Updated `project.manifest.toml` from project-only v2.3 to the entity-aware v2.4 default manifest schema.
- Clarified that directory and project manifests share `[manifest]` and `[entity]` headers before domain-specific sections.

## 0.1.2 - 2026-06-10

- Added proposal readiness levels and proposal quality rules.
- Expanded the project proposal template with governing standards, readiness, and risk sections.
- Added a filled CLI project proposal example.

## 0.1.1 - 2026-06-10

- Added SFDS two-layer suite metadata to the PPS standard manifest.
- Added a PPS suite map example.
- Clarified README, adoption, and validation language for suite conformance versus proposal readiness.

## 0.1.0 - 2026-06-10

- Added formal PPS suite wrapper.
- Preserved existing PPS draft as a reference.
